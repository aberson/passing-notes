Passing Notes — proposal

One read-only command, passing-notes status, prints every lane you may see as one table: what each lane is doing, who is waiting on whom, what is waiting on you, and what looks stale. A thin lane-status skill shows that table in chat. It never acknowledges a note, writes a card, rings a window or saves a file, and it never shows a note's subject or body.

Why this shape

One tested read, three consumers.

  • One call instead of many. The table needs every project's cards, inbox counts and bindings. Today that takes one card show plus one inbox per lane, for every project. status does it in one call with the CLI's existing ID checks.
  • Read-only is proved, not promised. Tests take a snapshot of the store before and after each run and require them to match. A canary string planted in a note body and in a subject must never appear in the output.
  • Reused later. user-pm and the Observatory lane board (P16) can read the same --json, so neither has to build its own scan.

Defaults worth your eyes. Reference by ID to tweak.

D47By default the CLI prints an aligned, ASCII-only table; --json is for tools. There is no tab-separated form.The table is readable from a bare PowerShell, and ASCII is safe on cp1252 consoles. No script parses status text, so nothing needs a stable TSV.Tweak: print TSV, like card show, and leave all rendering to the skill.
D48Counts only. A lane's open notes show as, for example, 3/2r (3 open, 2 needing a reply). Subjects are never shown; inbox is the drill-down.The privacy rule, and the board's richer views belong to Observatory (P16).Tweak: add --lane X to list one lane's subjects.
D49changed 2026-11-16 → P34. Was: Done lanes are hidden and counted per project as (N done). --include-done lists them.Most cards in the store are done; listing them buries the live ones.Tweak: always list them, at the bottom.
D50stale: an active, waiting or blocked lane whose card has not changed in 24 hours (--stale-after H changes this). no-doorbell, a separate flag: an active lane with no valid binding.These are two different problems: a lane that went quiet, and a lane nobody can ring.Tweak: a different number of hours, or one combined flag.
D51Notes are parsed with the store's one validated reader, which loads each whole file (at most 16 KiB) into memory. Nothing from the body reaches the output.A second, header-only reader could drift from the first. The canary test proves no body leaks. The protocol says "never shows a note body" to match (H4, settled).Tweak: add a header-only reader so the command never reads body bytes.
D52The Window column reads bound or not-bound from the binding files. Step 14's live window state is added later as an extra column and JSON field.This avoids duplicating Step 14's --live reader.Tweak: wait for Step 14 and ship live state from the start.

Later changes only add fields.user-pm and Observatory will both read it.Tweak: none recommended. The shape is pinned by a docs test.
D55The project list merges the folder names under messages, acks, cards, queues and wake. Every name is ID-checked, and anything else becomes a diagnostic.Some projects have cards but no messages.Tweak: list only projects that have cards.

Not in v1

Cut on purpose.

  • An HTML board or any saved file. That is P16, Observatory's.
  • Note subjects and bodies (D48).
  • A Heads Up column (D53).
  • Switching user-pm's Lanes section to status --json. That is a later additive Skill Mesh update.
  • Any change to card show or inbox output.
  • A special case for central. Until topology's Q5 switch, your central window sees only the five projects it is bound in. A bare terminal sees everything.
