Passing Notes — proposal

A small local CLI so Claude and Codex lanes leave each other notes, acknowledge them and publish a status card, without you relaying anything. The format is already in use by hand; this builds the tool and proves it across both hosts.

Why this shape

The pilot already proved the format, so the build proves the tool and the hosts.

A private pilot ran four notes and two acks across three Claude lanes by hand, all within v1's limits. The open risks are the parts the pilot never touched:

  • validation and no-overwrite writes under concurrency (Step 1);
  • a status card per lane (Step 2);
  • a Codex session reaching the private store through its sandbox (Step 3).

Model spend is isolated in its own step, so CLI iterations never burn credits.

What lands, step by step

Four steps — each one ends with something you can run or watch.

  1. 1
    Local private message CLIissue #1 · deep review

    The post, inbox, read and ack commands work over protocol v1, including kind, work, revision, supersedes, idempotency keys and the ack session line.

    Safety: exclusive temp files and renames that never overwrite; ids validated before any path is built; a store inside a Git repo refused with store-in-repo; note bodies framed as untrusted data. A test keeps the doc's Limits table and the code in agreement.

    →Afterwards: passing-notes post --project demo --from lane-a --to lane-b --subject "hello" --kind fyi --needs ack --body-stdin, then passing-notes inbox --project demo --lane lane-b
  2. 2
    Lane cardsnew issue · deep review

    card set replaces cards\<project>\<lane>.md through an exclusive temp file. card show lists every lane's host, state, item and update time. Two simultaneous writes never leave a partial card.

    →Afterwards: passing-notes card show --project demo answers "what is every lane doing" without asking you.
  3. 3
    Cross-host smokenew issue · deep review · real model spend

    Headless claude -p and codex exec sessions post, read, ack, reply and set their cards, in both directions, in a throwaway pn-smoke-<stamp> project.

    The verdict comes from the store only. A missing host fails the run, never skips it. The receipt is kept outside the repo and the store, and no transcripts are kept. Cleanup is guarded to the run's own folders.

    →Afterwards: uv run python tests/cross_host/run_smoke.py writes a pass/fail receipt under %LOCALAPPDATA%\passing-notes-smoke\receipts\.
  4. 4
    Real interactive Claude and Codex checkissue #2 · operatorwaits on skill-mesh v3 item 61

    One Claude window and one Codex window, as lanes claude-lane and codex-lane in project pn-uat, find each other's notes through their normal inbox checks and acknowledge them. Evidence (ids, ack names, times; no bodies) goes into the plan.

    →Afterwards: you never relay a message between those two windows again.

Agent defaults

Defaults worth your eyes. Reference by ID to tweak.

D1Python standard-library CLI.No runtime dependencies to install or audit; the store is plain files.Tweak: none recommended, because a dependency would add install friction on both hosts for no new behavior.
D2Immutable note files; separate atomic acks.No shared file for concurrent agents to rewrite, so no lost updates.Tweak: none recommended, because it's the pilot's proven shape.
D3Explicit inbox, read and ack.Reading is not receipt, and receipt is not agreement.Tweak: an ack-on-read flag, if lanes forget to ack.
D4Session/handoff hooks after the CLI, in this repo. Changed 2026-11-11: moved to skill-mesh (P11).
D5CLI contract: explicit --project/--lane, exit codes 0/2/3/4, store-in-repo guard.Identity never comes from host variables (Codex has no session id). Stable codes let skills branch.Tweak: verb names or exit-code values.
D6Per-project store folders.Note ids omit the project, so shared folders would mix two projects' central lanes.Tweak: none recommended, because the pilot has already migrated to it.
D7Python 3.11 or later; native Windows only in v1.Both hosts run natively on this machine; WSL paths would double the test matrix.Tweak: add WSL lanes later.
D8Store folders inherit %LOCALAPPDATA% permissions; never loosened.The per-user default is already private; the standard library can't set Windows ACLs cleanly.Tweak: explicitly restrict permissions with icacls on creation.
D9Exclusive .tmp, rename without overwrite, up to 5 new-hex attempts.Two writers can never share a temp file or replace each other's note.Tweak: the attempt count.
D10read frames the body as untrusted data.Note bodies land in agent context; the frame is a cheap reminder that they are data, not instructions.Tweak: the marker wording.
D11A test keeps docs/protocol.md and protocol.py in agreement, through a named Limits table.Hand-writing lanes follow the doc and the CLI follows the code; drift would split them silently.Tweak: none recommended, because it's the workspace's one-source-of-truth rule.
D12Kinds: handoff, change-notice, question, answer, blocker, commit-request, reservation, operator-relay, fyi.The approved set, with "question and answer" split so a reply is distinguishable.Tweak: merge question and answer back into one kind.
D13supersedes counts only from the same sender.Otherwise any lane could hide another lane's note.Tweak: none recommended, because this is a safety property.
D14Idempotency is checked before posting.Sequential retries are harmless; a lock file for the simultaneous case adds a third store folder for a rare race.Tweak: add a key-marker folder for strict idempotency.
D15Cards are mutable: an exclusive .tmp, then a replace; at most 8 KiB.A card is current state, not history; history lives in notes.Tweak: keep the previous card as <lane>.prev.md.
D16post requires --kind; hand-written v0 notes without it stay valid.Tool-written notes are always classified, and nothing breaks for lanes writing by hand.Tweak: make --kind optional.
D17Lane cards are their own step.Step 1 stays one vertical slice that fits one build context.Tweak: fold cards into Step 1.

Not in v1

Cut on purpose.

  • A board or dashboard page (Observatory owns it, P16)
  • Skill inbox hooks (skill-mesh v3 item 61, P11)
  • Daemons, polling loops or automatic wakeups beyond doorbells
  • Automatic dispatch, work assignment or approval
  • Network servers, sync between machines
  • WSL lanes and non-Windows hosts
  • A published package (editable tool install only)
  • A lane registry; project rules stay in each project
  • Strict idempotency under simultaneous posts
  • Forge's planned event log as a message store

Risks

What could bite, and the built-in answer.

Codex's sandbox can't write the store.Its workspace-write mode only reaches the working project.
P8 adds the store as a writable root. Step 3 runs under that same setting and records the mode; a denial fails the run.
Smoke cleanup deletes real notes.It runs inside your private store.
A guard refuses every path except the run's own pn-smoke-<stamp> folders; a unit test proves it; deep review.
Models improvise in the smoke.Headless sessions may skip a step or claim success.
The verdict comes only from store files; timeouts and turn caps; failure is never a skip.
Doc and code drift apart.Hand-writing lanes and the CLI disagree.
D11: the doc-parity test over the Limits table and examples.
Private data reaches the public repo.Notes, receipts or transcripts.
Synthetic fixtures; the store-in-repo guard; receipts outside the repo; no transcripts kept.
Step 4 stalls on skill-mesh.The hooks are owned elsewhere.
Step 4 is held, not blocking. The CLI is usable by hand and through the workspace instructions meanwhile.
