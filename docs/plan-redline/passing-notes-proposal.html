Passing Notes — proposal

Taking a turn on a shared resource becomes a Passing Notes object. When a lane releases its turn, the next lane is promoted and gets one doorbell, so nobody has to remember to write a "your turn" note. Passing Notes owns the order and the notification. The project's own lock stays with the project.

Why this shape

The stall was a turn that lived only in prose.

On 2026-11-15 the next engine turn went out as one fyi note to all. ring_reason never rings that kind of note, so four of six lanes waited about 80 minutes while the lock sat free. Three things follow from that:

  • Once the queue holds the order, the release itself can do the ringing. Nobody has to remember.
  • The ring goes through the existing doorbell path, so binding, done-card and already-acked checks all still apply.
  • Only the new holder is rung, which keeps the 2026-11-14 echo lesson: waiters further back cost nothing until their turn comes.

What lands, step by step

Six steps after the pending Step 4. Each one ends with something you can run or watch.

  1. 5
    Queue verbs: reserve, release, show, cancelnew issue · deep review

    A lane that reserves a free resource becomes its holder. Later lanes join the line and are told their position and who holds it now. Release promotes the next waiter. Repeating a reserve or a release changes nothing. Concurrent reserves from several processes each land exactly once. Queue state lives only under the store root, and a root inside a Git repo is refused as it is for notes.

    →Afterwards: passing-notes reserve engine --project demo --lane lane-a, then passing-notes queue show engine --project demo
  2. 6
    Release rings the next holdernew issue · deep review

    With three lanes in line, a release gives the second lane one note and one doorbell, and the third lane gets nothing until its own turn. A lane whose card is done is skipped with a diagnostic. If the ring fails, the promotion and the note stay, and the command exits 5. Lane rules then tell lanes to take turns through the queue.

    →Afterwards: passing-notes release engine --project demo --lane lane-a prints the new holder and its wake: line.
  3. 7
    Coordinator config, reordering and releasenew issue · deep review (raised by plan-review)

    queue config names the coordinator (main until set) and per-resource turn minutes. Only the coordinator can reorder waiters, and a move rings no one. release --holder lets the coordinator end a dead holder's turn, which promotes and rings the next waiter.

    →Afterwards: passing-notes queue move engine --project demo --lane main --waiter lane-c --to 1
  4. 8
    Queue check and stall alarmnew issue · deep review

    A read-only check suited to hooks and loops. It reports a holder past its deadline (it never evicts) and a stalled turn. --ring rings once per stall, and a second run rings nothing. It reports a lock mismatch only when --lock-holder is given.

    →Afterwards: passing-notes queue check --project demo ends with queue-check: past_deadline=0 stalled=0 mismatch=0
  5. 9
    Waking allnew issue · code review

    The refusal stays (exit 2, nothing written) and now names --to <lane> and passing-notes reserve. This is the only existing message that changes.

    →Afterwards: passing-notes post --project demo --from main --to all --wake … names the way to reach the lanes.
  6. 10
    Live queue smoke with real lanesnew issue · operator

    After reinstalling the lane skills for both hosts and restarting them, synthetic project pn-queue-uat with three Claude lanes and one Codex lane: one release gives exactly one doorbell. A ring to an unbound lane is missed, then the stall alarm rings that lane and main once, and a second check rings nothing. The evidence is ids and wake lines, never note bodies.

    →Afterwards: you've seen a released turn wake the next real window.

Agent defaults

Defaults worth your eyes. Reference by ID to tweak.

D20Resource names use the lane-id grammar: lower-case words joined by hyphens, at most 32 characters, Windows device names refused.The name becomes part of a file name, and one grammar for every id is simpler.Tweak: allow dots or capitals, or a longer limit.
D21reserve and release are top-level commands, while show, move and check sit under queue; cancel is reserve --cancel. --lane always names the caller, as it does for ack and card set.This follows the seed's shape and the CLI's rule that identity is explicit.Tweak: put everything under queue, or make cancel its own verb.
D22Repeating a reserve or release changes nothing. A waiter that tries to release is refused and told to cancel; a holder that tries to --cancel is refused and told to release.Retries stay harmless, as they are for post (D14), and the two refusals catch a lane that has its role wrong.Tweak: treat cancel by the holder as a release.
D23The turn note goes from the releasing lane to the new holder as kind: reservation, needs: reply, subject "Your turn on <resource>". It carries a turn idempotency key, and the CLI writes its body from fixed text.ring_reason already rings this note unchanged, and a retried release finds the note instead of posting a second one.Tweak: send it from the coordinator instead of the releasing lane.
D24At promotion, a waiter whose card is done is dropped from the line with skipped <lane>: card is done and never rung. A waiter with no card is promoted, and the doorbell path decides from there.A closed lane can't take a turn, and a lane that reopens reserves again.Tweak: keep it in line and pass over it.
D25If the ring fails on release, the promotion and the note stay, wake: not delivered is printed, and the command exits 5.This is the same contract as post --wake, and queue check then reports the stall.Tweak: exit 0 and print a warning.
D26For each stall, queue check --ring posts one note to the holder and one to the coordinator. Their idempotency keys mean a second run in the same stall rings nothing and prints stall: already rung.The run needs no queue write to stay idempotent.Tweak: ring the holder only.
D27queue move reorders waiters only, never the holder, and rings no one.This keeps ringing to one doorbell per release.Tweak: ring a lane that a move puts at the front.
D28queue check prints one tab-separated row per finding (past-deadline, stalled, mismatch), then one pinned queue-check: summary line. It exits 0 unless the store is unusable.A hook can read it the same way it reads inbox --summary.Tweak: exit non-zero when a finding exists.

Not in v1

Cut on purpose.

  • Reading, taking, writing or deleting any project's own lock files.
  • Fixing a mismatch automatically.
  • Eviction by timeout; only the coordinator's explicit release --holder (P26) ends another lane's turn.
  • Any change to ring_reason, UNBLOCKING_NEEDS, or the note, ack and card formats.
  • Queue commands writing cards; a card stays its own lane's.
  • A daemon, scheduler or polling loop; queue check runs when something runs it.
  • Dispatch: a turn is a place in line the lane asked for, never assigned work.
  • The woken-Codex sandbox suspect from the seed, which stays a seed.

Risks

What could bite, and the built-in answer.

Lane identity is self-declaredAny process can claim to be the coordinator.Documented as identity, not security, as cards already are.
A stale lock broken during a writeUnder P24's record+lock, an update could be lost.The lock is held only for the read-modify-write, the stale timeout is far longer than that, and a concurrency test covers it.
Codex doorbells are queued, not deliveredqueued doesn't prove the lane saw it.The existing wake states stay separate, and queue check catches a turn nobody picked up.
Double holdersA lane takes the project lock without a turn.Reported only when the project passes --lock-holder; never fixed.
No evidence beyond one resource and six lanesThe limits may be wrong.A bounded QUEUE_MAX_WAITERS with a clear refusal.
