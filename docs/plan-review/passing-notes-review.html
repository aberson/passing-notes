Give the Claude and Codex smoke its own step?

Step 1 currently holds both the CLI and a harness that drives real Claude and Codex sessions. The step-sizing rule allows one behavior per step. Kept together, CLI review iterations can spend model credits, and a Codex sandbox problem would block an otherwise finished CLI.

  2. BKeep the smoke inside Step 1. It runs at Step 1's final DONE check.

How do Codex lanes get write access to the store?

Codex runs commands inside a sandbox. A workspace-write sandbox rooted in a project can only write inside that project, so passing-notes post and ack would fail to write %LOCALAPPDATA%\passing-notes. Claude-only lanes never hit this, which is exactly why the pilot couldn't test it. The exact Codex config key is checked during the build.

  1. AAdd the store root as an extra writable folder in the Codex config that lanes use (for example sandbox_workspace_write.writable_roots), and have the smoke run with that same config. Codex lanes can then write the whole store, as Claude lanes already can.Recommended
  2. BRun Codex lanes without sandbox write limits. Simpler, but much broader access.
  3. CDon't decide yet: run the smoke, record what fails, and come back to this.

How do lanes in other projects run the CLI?

uv run passing-notes works only inside the passing-notes checkout, and lanes work in other repos. The smoke will use whichever method you choose.

  1. Auv tool install --editable <passing-notes checkout>: this puts passing-notes on PATH for both hosts, and it follows the checkout as the code changes.Recommended
  2. Buv run --project <checkout> passing-notes ...: no install, but a longer command, and uv may need write access to its cache inside Codex's sandbox.

Limits and evidence for the real-model smoke?

One run is about six headless sessions: in each direction, one posts, the other reads, acknowledges and replies, and the first then reads the reply and acknowledges it. The plan doesn't yet cap time or turns, or say where evidence goes, and AGENTS.md forbids committing agent transcripts.

  1. AAccept these defaults:
    • a 300-second timeout per host call;
    • a turn cap of 8 for Claude;
    • one receipt per run, saved outside both the repo and the store, recording CLI versions, the models reported, the Codex sandbox mode, note ids and the verdict;
    • no raw transcripts kept.
    Recommended
  2. BChange the limits or the receipt location. Say what you want instead.
