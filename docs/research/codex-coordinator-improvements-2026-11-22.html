Decisions needed from you

D1. Who holds the coordinator seat. Decided 2026-11-22 (your word, relayed by Main): use Codex for image generation only. Claude holds the coordination and development lanes, and the ranking below assumes that. What would make Codex workable elsewhere is kept separately, in Which host.

D2. Standing authority to stop processes. May the coordinator stop processes the tooling identifies as safe, such as WSL VM memory, orphan codex app-server processes and process trees of done lanes, when free RAM drops below a floor you name, without asking first? It would report afterwards. Unidentified processes and other people's windows would still need your OK. Recommended: yes, with a 4 GiB floor.

D3. Clearing the note backlog. May the coordinator bulk-acknowledge fyi and broadcast notes older than 48 hours? And should a broadcast's "needs reply" expire once the sending lane is done? Recommended: yes to both. An ack still means "received", nothing more.

D4. Limit on stand-in mains per window. Recommended: the Claude dev/main window stands in for at most three project mains at once. Past that, it opens a project main window with lane-open. Today the number is unlimited (docs/lane-rules.md:384).

D5. Closing done Claude windows automatically. May the coordinator close a done Claude lane window that lane-open launched, once the helper proves the card is done, the session is idle and the process tree is the one recorded at launch? Recommended: yes. Windows you opened yourself, including the coordinator's own window, stay yours to close (details).

Bottom line

The coordinator was not blocked by permissions. Every one of its 1,155 turn settings used approval never with full access, and it hit no sandbox denials. It also answered the notes it touched quickly: the median time to acknowledge was 0.7 minutes. It failed for four reasons that add up:

  1. Nothing told it to keep things tidy. Neither host's instructions give a coordinator a recurring sweep: free memory, idle lanes, unacknowledged backlog, old operator decisions, stale cards. The routine check they do name is tied to the turn and "never polls" (docs/lane-rules.md:148-155), and it names a different flag (--needs-attention) from the one the CLI documents for coordinators (--coordinator-attention, docs/cli.md:550). So cleanup happened only when you asked for it.
  2. One context held five or six jobs. It acted as dev/main and as main for say-no-more, dev-observatory, passing-notes and skill-mesh at once. A goal kept generating its own turns (346 turns started with no user message). Its context was compacted 72 times, and every compaction lost its working picture.
  3. Long turns blocked its own mail. 1,098 sleep calls inside turns, 11.5 h in total, and turns of up to 50 minutes. Codex delivers a doorbell only when the window is idle, so notes queued behind those turns ("already has an active writer"). 204 of its 541 doorbells were for notes it had already acknowledged.
  4. It could see a problem but not decide what to do about it. It listed processes 1,606 times and checked RAM 574 times, but no tool maps a process to its lane and its memory use, and no rule says what is safe to close. When the close helper said closeable:false it stopped. It never used the stand-in-and-close procedure the Claude coordinator used, which is allowed but written down nowhere.

Each time it missed something, it started a new repair lane (coord-rule, coord-only, window-close, window-inventory, status-ux). Each lane fixed one tool. None of them added the routine sweep that would have caught the next miss.

Most of these causes do not depend on the host. With Claude now holding coordination (your 11-22 direction), the top fixes still apply: a sweep the CLI computes and a cadence to run it (R1, R2); closing done Claude windows (R3), which is why the two SAFE TO CLOSE windows stayed open; and a written route for closing idle lanes with no window (R4).

Closing done Claude windows and the coordinator window

What happened. On 11-22 the two Claude close-only windows (practice-plumber step5-fix-developer, skill-mesh step10-developer) printed SAFE TO CLOSE THIS WINDOW but stayed open. That is the current design, not a malfunction. lane-close never closes its own window. close_done_window.py only accepts done Codex cards: card.host != "codex" refuses at lines 292, 359, 388, 430 and 471. So every Claude window, and any window you opened yourself, waits for you.

Why it can be fixed cheaply. lane-open launches Claude windows the same way it launches Codex ones. open-lane.ps1:175 starts powershell.exe -NoExit -File <launcher>, the launcher runs claude -n <title>, and the script returns the PID (:180). The launcher path under the Passing Notes state folder is a unique identity in the process command line. Claude windows also have better liveness evidence than Codex: status already reports busy, idle and wakeable for Claude bindings. The safe-close design (process handles, "no host process started after done", one console host) carries over; only the host's process-tree shape differs.

What not to change

  • Checks stay tied to turns, with no background monitor. The sweep is a command run at fixed points, not a daemon. A watcher turns every event into a turn, and that cost is what dev/.claude/rules/subagent-economy.md rule 4 exists to cap.
  • The close helper's strict identity checks. When it refused (closeable:false), it was right not to guess. The fix is a better map (R4) and a documented route for idle lanes (R5), not looser checks.
  • An ack means "received". Clearing the backlog in one step (R7) must not turn an ack into agreement or completion.
  • Topology. A lane bound to one project sees only that project, as this lane found out. Cross-project sweeps belong to dev/main.
  • The operator-said: relay, ringing only to unblock, and "dispatch, then end the turn". They worked. The failures came from breaking them, not from following them.
  • The coordination-only rule for main (dev 7229dbc0). It stopped the implementation work as soon as it landed.
  • The Claude Stop hook, the coordinator-attention brief, and the Codex safe-close helper. The sweep and W1 build on them.
  • No new (y/n) prompts. The decisions D2–D5 give standing authority once, so the sweep never stops to ask.
