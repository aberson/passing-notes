What a lane can do now

Every new view is an opt-in flag, except card set’s overlap rows, which print only when an overlap exists. Otherwise output is byte-identical to before. The examples use synthetic ids.

Ring only when it matters: --wake-if-needed

Posts the note every time and rings only an eligible one. An ineligible note is stored, its id and a note: line print, then wake: not rung (<why>); the lane sees it at its next inbox check, and it exits 0. An idempotent retry prints the same not rung line again with exit 0, and writes nothing new.

passing-notes post --project example-project
  --from lane-a --to lane-b --kind fyi
  --needs ack --subject "Docs merged"
  --idempotency-key lane-a-20261115T1410Z
  --wake-if-needed --body-file note.md

Strict --wake refuses first

When ring_reason would not ring the note, post --wake now refuses before anything is stored: exit 2, error code wake-not-needed, nothing written. The message names why (including a --reply-to note that is not in the store) and points at --wake-if-needed. Use plain --wake when you must be told a ring is impossible. wake send on a note already posted keeps exit 5.

Inbox in one line: --summary

Prints one pinned summary line instead of the note lines. oldest_age_min is - when nothing is listed; stale is - without --stale-after. Read-only: it never changes the store.

passing-notes inbox --project example-project
  --lane lane-b --summary --stale-after 30
inbox-summary: count=<n> oldest_age_min=<m|-> stale=<k|->

Spot what has waited too long: --stale-after

A whole number of minutes, at least 1 (anything else is exit 2). A listed note that needs reply and is older than that many minutes is flagged stale, after acked and superseded in the flag list; other needs are never stale. Ages are compared in seconds, so a huge value cannot overflow.

See shared claims: card show --overlaps

After the card lines, one tab-separated row per owns or holds entry that two non-done lanes share: overlap, lane-a, lane-b, entry-a, entry-b, with lane-a sorting first and each pair once. Read-only, and only without --lane.

passing-notes card show --project example-project --overlaps
overlap	lane-a	lane-b	src/	src/passing_notes/cli.py

Warned at claim time: card set

Setting a card that is not done prints the same rows for that lane straight after card set: <project>/<lane> at <time>. Advisory and fail-open: it refuses nothing, and a store that cannot be scanned adds no rows and leaves the exit code alone.

The rule is case-insensitive and normalises \ to /, collapses //, drops ./ and a trailing /; an entry overlaps another equal to it or under it at a / boundary, so src/ overlaps Src/x but src does not overlap srcx.

New doorbell wording

The woken lane still gets the note id and never its content, and now hears that acking is not the job:

New Passing Note <note-id>. Read it and respond through Passing Notes. Acknowledging
this doorbell is not the deliverable: a finished item always posts its own handoff note.
If you already acknowledged this note or your card is done, stop: post nothing more
about it and ring no one.

lane-open brief line

Every opened lane’s brief carries this exact line, and each finished item posts its own --kind handoff note to the coordinator:

start each item with /user-build-route;
compile/test before hand-off;
every finished item gets its own handoff

lane-close SAFE TO CLOSE line

In SELF mode, when the lane closed, the very last line of output, printed after any wake errors, is exactly this. A NOT CLOSED run never prints it.

SAFE TO CLOSE THIS WINDOW - lane <lane> closed, handover <id>

How post decides

The same ring_reason answers for a draft and for the note published from it, so the eligibility check can run before anything is stored.
