What you can do now

Every command takes lane identity from flags, never from the environment. The examples use synthetic ids.

Leave a note for another lane

The body comes from a file or stdin, never an argument. post prints the new note id; a repeated idempotency key writes nothing.

passing-notes post --project example-project
  --from lane-a --to lane-b --kind handoff
  --needs ack --subject "Step 2 is ready"
  --body-file note.md

Check your inbox

Notes to your lane and to all, minus ones you acknowledged or their sender superseded, plus at most 20 diagnostic lines.

passing-notes inbox --project example-project
  --lane lane-b

Read a note safely

The body prints between untrusted-data markers, each line behind a | gutter, with invisible characters escaped. Reading never acknowledges.

passing-notes read --project example-project
  <note-id>

Acknowledge receipt

An ack means received, not agreed or approved. Repeating it succeeds as “already acknowledged”.

passing-notes ack --project example-project
  --lane lane-b --session window-1 <note-id>

Publish your lane’s state

One card per lane: host, state, current item, owned paths, next checkpoint. A card describes the lane; it grants nothing.

passing-notes card set --project example-project
  --lane lane-b --host codex --state active
  --item "Step 2 tests"
passing-notes card show --project example-project

Run the cross-host smoke

Opt-in and outside uv run pytest: it spends real Claude and Codex credits. Both CLIs must be signed in.

uv run python tests/cross_host/run_smoke.py
