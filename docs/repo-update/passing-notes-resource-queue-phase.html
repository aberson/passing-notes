Resource queue phase: a released turn now wakes the next lane

A shared resource, such as an engine lock or a play checkout, now has a turn order that Passing Notes keeps. Lanes reserve a turn and see the line. When a lane releases, the next waiter is promoted and rung, so nobody has to remember to send a "your turn" note. Passing Notes owns order and notification only. It never reads or touches a project's own lock files.

The incident behind it

On 2026-11-15, in a sibling project where a coordinator and six Codex lanes share one engine lock, four of the six lanes did no work for about 78 minutes (21:32Z to 22:50Z) while the lock sat free. The coordinator had posted the next turn order as one fyi note to all. A note like that is not eligible to ring, the order existed only in note prose, and no one rang the next lane. Each lane was correctly waiting to be told.

Recovery came only when the coordinator re-sent each turn as a --needs reply --wake note to one named lane. This phase makes that the default: the turn is a Passing Notes record, and releasing it is what rings the next lane.

What the operator and lanes can do now

Each queue line is tab-separated and starts with its kind, so a project's own lock script can parse it. The examples use synthetic ids.

Take a turn: reserve

On a free resource you hold the turn at once. Otherwise you join the end of a FIFO line. --minutes sets the turn length (default 60, or the resource's configured default); --reason adds one short line. Repeating it writes nothing. --cancel leaves the line.

passing-notes reserve engine --project example-project
  --lane lane-a --minutes 40 --reason "Step 2 soak"

See the order: queue show

For each resource, or only the one named, the holder line, then the waiter lines in order. It writes nothing. A resource never reserved shows as free.

holder	engine	lane-a	<granted_utc>	<deadline_utc>
waiter	engine	1	lane-b	<since_utc>

End your turn: release

The first waiter becomes holder at once. Passing Notes posts it one reservation note (needs: reply, key turn-<resource>-<grant_seq>) and rings only that lane. Waiters further back get nothing. A waiter whose card is done is skipped and never rung. A failed ring keeps the promotion and the note and exits 5.

The coordinator steers the queue

One lane per project, main until queue config --coordinator names another, may set stall and turn minutes with queue config, reorder waiters with queue move (--to N or --after LANE), and end a dead window's turn with release --holder, which promotes and rings the next waiter exactly as the holder's own release would. Any other lane gets not-coordinator (exit 2).

Catch a stall: queue check

Reports past-deadline, stalled and, with --lock-holder, mismatch rows, then one summary line. It writes nothing and evicts no one. With --ring --lane L it rings the holder and the coordinator once per stall.

passing-notes queue check --project example-project
  --lane main --ring
queue-check: past_deadline=<n> stalled=<n> mismatch=<n>

Waking all points to what works

post --to all --wake (and --wake-if-needed) is still refused before anything is written (exit 2, invalid-argument). The message now names the routes that work: ring one lane with --to <lane>, or take turns with passing-notes reserve. This is the phase's one change to existing output.

How a turn moves

Release rings one lane. A stall alarm backs it up when that lane does not answer.
